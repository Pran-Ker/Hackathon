## 5. Info.plist additions (Sources/Hologram/Info.plist)

TestShip's plist has none of these; all must be added:

- `NSCameraUsageDescription` — "Capture a photo or video to turn into a hologram." (only if in-app camera capture is included; photo-library picking via `PhotosPicker` needs no key).
- `NSMicrophoneUsageDescription` — required if video capture with audio.
- `NSPhotoLibraryAddUsageDescription` — for "save to Photos" on the share screen.
- `NSLocalNetworkUsageDescription` — the backend is an HTTP server on the Mac's LAN IP; iOS prompts for local-network access.
- App Transport Security: the backend is plain HTTP. Add
  ```xml
  <key>NSAppTransportSecurity</key>
  <dict><key>NSAllowsLocalNetworking</key><true/><key>NSAllowsArbitraryLoads</key><true/></dict>
  ```
  `NSAllowsLoadsArbitrary...=true` is the blunt option that also covers non-RFC1918 addresses (e.g. tailscale/ngrok http). Fine for TestFlight internal testing; tighten before App Store review.

**Effort: 10 min.**

## 7. Viewer URL scheme for the app

App-facing contract (what the Swift code assumes):

- `POST {base}/api/scene` — multipart `file` + `prompt` → Scene3D JSON, which must include a stable **`scene_id`** (the cache key, e.g. sha16 like `/imagine` uses) so the app can build the viewer URL and re-open old scenes. **`scene_id` is not in the Scene3D contract as written — adding it (additive) is a requested change.**
- `GET {base}/api/scene/{id}` — returns the same Scene3D JSON (needed for re-open from history and for polling).
- `GET {base}/app/hologram.html?scene={id}` — static hologram viewer; it fetches `/api/scene/{id}` itself and loads assets by the **relative** URLs in the JSON. Relative (or request-host-rooted, like `/imagine` already does) URLs are essential: the phone reaches the Mac by LAN IP, so absolute `localhost` URLs break.
- All asset URLs (`frame_url`, `glb_url`, `cutout_url`) served under the existing `/files` static mount.

Because app and viewer share `{base}`, the WKWebView is same-origin with the API — **no CORS work needed**.

## 8. Requested backend/viewer changes (not done by this app; needed before the app works end-to-end)

Verified current state of `pipeline/pipeline/server.py`: it exposes `/api/health`, `/api/runs`, `/api/edit`, `/imagine`, `/imagine/batch`, `/files` — **there is no `/api/scene` and no `/app/hologram.html` yet.** Requested:

1. `POST /api/scene` per the Scene3D contract, **plus `scene_id` in the response** (additive).
2. `GET /api/scene/{id}` (read-back of the cached manifest).
3. Mount/serve the hologram viewer at `/app/hologram.html` from the FastAPI service (the current studio UI lives at `pipeline/outputs/imagine/studio.html` under `/files`; the hologram viewer should get a first-class `/app/` mount) and make it accept `?scene=<id>`.
4. Strongly recommended: async job pattern — `POST /api/scene` returns `202 {scene_id, status:"processing"}` fast, `GET /api/scene/{id}` reports `status: processing|done|error`. iOS backgrounds apps aggressively; a 5-minute open HTTP request will die if the user locks the phone. If this isn't done, the app compensates with a 900 s timeout and "keep the app open" copy, and results are still recoverable via the content-addressed cache (re-POST the same bytes+prompt → cache hit).
5. Raise/verify the request body size limit for video uploads (a 10 s iPhone video is 20–60 MB).
