# Mesh — image → 3D component

The mesh path turns a single product photo into an optimized 3D GLB (plus a
typed react-three-fiber component). `mesh.html` is the viewer; the pipeline API
does the generation.

## Run both servers

```bash
# 1. Pipeline API (image → 3D). Restart this after editing server.py.
cd pipeline
uv run uvicorn pipeline.server:app --port 8000
#   stale process? lsof -ti:8000 | xargs kill -9

# 2. Viewer (Vite dev, hot-reloads automatically).
cd viewer
npm run dev            # http://localhost:5173/mesh.html
```

Open **http://localhost:5173/mesh.html**. `npm run build` produces a static
`dist/` with both `index.html` (splat) and `mesh.html`.

## Demo preset flow (the reliable path)

The bottom bar has instant demo presets that load pre-baked GLBs from
`viewer/public/` with **no wait**: **Sneaker**, **Chair**, **Plant**. Sneaker
loads on startup. Use these to guarantee something on screen; the live drag-drop
gen is the "wow" but takes minutes.

The Plant button auto-hides if `viewer/public/plant.glb` is missing.

## Live generation (drag & drop)

Drag any image anywhere onto the window. It POSTs to `/imagine` and loads the
returned GLB. The endpoint is **synchronous (~2–3 min)**, so the viewer shows a
progress card with an elapsed timer and staged labels (isolating subject →
generating 3D mesh → compiling & optimizing) driven on a time estimate — the
sync endpoint reports no real progress. The previously loaded model stays dimmed
behind the card. On success a caption shows the detected name/tags and the
`size_before → size_after` reduction. On any failure an error toast appears and
the current model is kept (never wiped).

## Share over Wi-Fi (LAN)

Both servers already bind every interface (`uvicorn --host 0.0.0.0`, `http.server
--bind 0.0.0.0`), so anyone on the same network can use it — open

```
http://<this-machine-LAN-IP>:8778/studio.html
```

The API prints the exact LAN URLs on startup (`GET /api/health` also returns
`lan_ip`). Every URL the API returns (`glb_url`, `component_url`) is derived from
the **request host**, not a hardcoded `localhost`, so a model generated by a
phone/laptop loads on that phone/laptop. The studio POSTs to
`location.hostname:8000`, so it follows whichever host you opened it from.

## Durable + idempotent

Each generation is content-addressed by the SHA-256 of the uploaded bytes and
written to `outputs/imagine/<sha16>/`. Consequences:

- **Idempotent** — re-uploading the same image (or a retry after a dropped
  connection) returns the existing result instantly (`"cached": true`) instead of
  re-running the ~3–4 min pipeline. Concurrent identical uploads are de-duped via
  a per-content lock, so only one runs.
- **Durable** — `result.json` is written per run and `manifest.json` is rebuilt
  from disk on startup and after every generation, so the studio sidebar (and
  `GET /api/runs`) survives restarts. Legacy timestamp-named runs are preserved.

## Interactive API docs (Swagger)

FastAPI auto-generates live docs — with the server running:

- **Swagger UI:** `http://<host>:8000/docs` (try requests in the browser)
- **ReDoc:** `http://<host>:8000/redoc`
- **OpenAPI spec:** `http://<host>:8000/openapi.json` (also exported to
  `pipeline/openapi.json` — import it into Postman / Swagger Editor)

## Batch: several images in parallel

`POST /imagine/batch` takes 2–8 images in the `images` field and runs them
through the pipeline **concurrently** (wall-clock ≈ the slowest single image,
not the sum). Each result is independent — one failure doesn't sink the others,
and duplicates return instantly as cache hits.

```bash
curl -X POST http://<host>:8000/imagine/batch \
  -F "images=@a.jpg" -F "images=@b.jpg" -F "images=@c.jpg"
```
```json
{ "count": 3, "results": [
  { "filename": "a.jpg", "ok": true,  "result": { ...ImagineResponse... } },
  { "filename": "b.jpg", "ok": false, "error": "3D generation failed: ..." }
]}
```

## Ready-to-use Three.js code in the response

Both `/imagine` and `/imagine/batch` return the code, not just URLs:

- `threejs_html` — a drop-in standalone `.html` page that renders the model
  (paste into a file, open it). Always present.
- `threejs_native` — a self-contained native Three.js component
  (`createModel()`), geometry inlined, no loader/asset needed. Present when the
  transpile step produced one; `null` otherwise or with `?native=false`.

Add `?native=false` to omit the (large) native source from the payload.

## `/imagine` contract

```
POST http://<host>:8000/imagine
  multipart/form-data, field "image" = the photo (PNG/JPG/WEBP)

200 OK
{
  "glb_url":       "http://<host>:8000/files/imagine/<sha16>/compiled/....glb",
  "component_url": "http://<host>:8000/files/imagine/<sha16>/compiled/....tsx",
  "name":          "sneaker" | null,
  "tags":          ["shoe", "footwear", ...],
  "size_before":   <bytes, raw GLB>,
  "size_after":    <bytes, optimized GLB>,
  "cached":        true | false,         # true = returned an existing result
  "threejs_html":   "<!doctype html>..." # drop-in standalone renderer
  "threejs_native": "createModel()..."   # self-contained component, or null
}

400 { "error": "Upload must be an image (PNG, JPG, or WEBP)." }   # bad/empty upload
500 { "error": "3D generation failed: <detail>" }                # pipeline error
```

Other endpoints: `GET /api/health` (liveness + `lan_ip`), `GET /api/runs`
(durable manifest). Errors are JSON (never an HTML 500 page) and go through CORS
so the viewer can read `error` off the body. Static outputs are mounted at
`/files`; CORS allows any origin (dev).
